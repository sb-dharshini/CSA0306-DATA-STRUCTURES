Slide 03 · Data Structure Justification

Why LIFO Stacks Succeed Where Counters Fail

Balanced multi-type delimiters form a Context-Free Grammar (Dyck language). Quantity alone is insufficient; nesting order must be remembered.

Naive Integer Counter on ([)]

( → 1 · [ → 2 · ) → 1 · ] → 0

False Positive: Reports Valid because final count equals 0.

LIFO Stack Automaton on ([)]

Push '(' · Push '[' · Read ')' ≠ top '['

Accurate: Rejects mismatch at column 3 immediately.

All three fault classes—Mismatch, Stack Underflow, and Unclosed EOF—are detected in O(n) time.

Slide 05 · Expression Representations

Infix Ambiguity vs. Parenthesis-Free Notations

Infix (Human Input)

(3 + 4) * 2

Operator sits between operands. Requires parentheses and precedence rules to disambiguate.

Postfix / RPN (Stack VM)

3 4 + 2 *

Zero parentheses needed. Evaluates in one strict left-to-right pass (JVM, WebAssembly, CPython).

Prefix / Polish (AST Pre-Order)

* + 3 4 2

Operator precedes operands (Jan Łukasiewicz, 1924). Matches Pre-Order traversal of the AST.

In-order AST traversal recovers Infix; Post-order gives Postfix; Pre-order gives Prefix.

Slide 06 · Dijkstra’s Shunting-Yard (1961)

Precedence, Associativity & Operand Pop Order

Operator Stack Pop Rule

Pop top to output while top is not an opening bracket and:

Left-Assoc (+ - * / %): prec(top) ≥ prec(op)
Right-Assoc (^): prec(top) > prec(op)

2 ^ 3 ^ 2 → "2 3 2 ^ ^" → 2 ^ 9 = 512

RPN Operand Pop Order

LIFO order places the right-hand operand on top of the stack:

right ← valueStack.pop()
left ← valueStack.pop()
valueStack.push(left op right)

"10 3 -" → right=3, left=10 → 10 - 3 = 7

Context-sensitive lexing also tags leading '-' or '-' after '(' / operator as unary negation (u-).
